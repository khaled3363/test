One Airtable base that holds the standard assemblies (typicals), the generic pieces they are built from, the supplier articles that implement each piece, and the archive projects that prove which ones are typical. Designers browse it; the AI layout skill and the pCon handover read from it.

Import plan

  1. Create the base and tables in this order: Series, Products, Projects, Generics, Generic→Product, Typicals, Composition. Links need the target table to exist first.
  2. Load reference data from CSV. Series aggregated from product-stats.csv, Products from product-stats.csv plus dimensions and prices from data/catalog.csv, Projects from data/archive/projects.csv. This is flow D run once.
  3. Load the catalogue. Generics from the tables in generics/catalog.md (85 rows), Generic→Product from mapping/generic-to-product.csv (75 rows, column for column), Typicals and Composition from the four typicals/*.md files (26 assemblies). Everything starts as Draft or Proposed.
  4. Attach images. Plan render and isometric per typical and per generic. These can be generated from the catalogue dimensions, or taken from the Blender and pCon renders in tests/.
  5. Build the four interface pages and run flow C with the trial protocol already in review/designer-trial-protocol.md. The write-back script closes the loop so the AI skill reads the same confirmations.

All of steps 1 to 3 can be scripted through the Airtable connector in this session once you approve the schema. Nothing is created until then.

Decisions before building

Which archive rule counts as "typical"? Rule C (one vote per project, finals only) with a threshold of 6 projects drives the Typical flag in flow D. Confirm the threshold.
Tiers. Standard / Better / Best per mapping line, filled in flow C. Lines imported from the library carry Standard or Best; nothing is Better yet.
Removed from draft 1, to keep the base to the four flows. Manufacturers table (now a select on Series, with the Kastel → Las Mobili note), Rules table (compliance stays with the skill and the markdown; each typical keeps its geometry rules as text), and X / Y / Rotation on Composition (placement lives in placement.csv, the plan render is an attachment).
