Offispace Typicals Base

One Airtable base that holds the standard assemblies (typicals), the generic pieces they are built from, the supplier articles that implement each piece, and the archive projects that prove which ones are typical. Designers browse it; the AI layout skill and the pCon handover read from it.

Where it sits

Import plan

  1. Create the base and tables in this order: Manufacturers, Series, Products, Generics, Typicals, Composition, Generic→Product, Projects, Rules. Links need the target table to exist first.
  2. Load reference data from CSV. Manufacturers and Series from product-stats.csv (aggregated), Products from product-stats.csv plus dimensions and prices from data/catalog.csv, Projects from data/archive/projects.csv.
  3. Load the catalogue. Generics from the tables in generics/catalog.md (85 rows), Generic→Product from mapping/generic-to-product.csv (75 rows), Typicals and Composition from the four typicals/*.md files (26 assemblies).
  4. Attach images. Plan render and isometric per typical and per generic. These can be generated from the catalogue dimensions, or taken from the Blender and pCon renders in tests/.
  5. Build the interfaces and hand the designer the trial protocol already in review/designer-trial-protocol.md. Every confirmation in Airtable is then written back to the markdown by a small script, so the AI skill and the base stay in step.

All of steps 1 to 3 can be scripted through the Airtable connector in this session once you approve the schema. Nothing is created until then.

Decisions before building

Which archive rule counts as "typical"? The library's own analysis offers three: all drawing versions (A), final drawings only (B), or one vote per project (C). The schema stores B and C per series and product; the "Typical" flag on a product defaults to rule C ≥ 6 projects. Confirm the threshold.
Tiers. Good / Better / Best per generic are TBD in the library. The base reserves a Tier field on each mapping line; the design team fills it.
Kastel is dropped (Las Mobili replaces it, decision 2026-10-09). Kastel products stay in the archive tables for evidence but are marked Status = Replaced, and the SOFA-BOOTH-4 mapping starts empty.
Source of truth. Recommended: Airtable is the master for mappings, tiers and typical status; the markdown stays the master for geometry rules and clearances until the base has proven itself in the designer trial.
